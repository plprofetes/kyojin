# Sprint 6: ship it (upstream PR, download-and-use) and scale

[previous sprint](../s5-harden/README.md) · [all sprints](../../README.md) · [deferred](../../deferred.md)

**Goal.** The Windows path leaves the PM branch in a reviewable form (upstream PR), a Windows user can download a release and use it without compiling, and the next model class (the 85 GiB Qwen3.8-Flash-Next pack) is tried against the measured memory ceiling.

**Exit criteria.**
- An upstream PR branch exists that contains only the code, scripts, tests and user docs (PM files stay in the fork's `main`), with a link-consistent doc set and a reproducible recipe.
- A CI job builds the Windows ROCm wheel (manual trigger), or the reason it cannot is documented with numbers.
- An installer + release bundle takes a Windows user from a download to `READY` without building the extension; tested on a profile without Visual Studio (to learn what is really required).
- Qwen3.8-Flash-Next 2.18bpw is loaded (or the failure is explained); memory numbers recorded.

Carried over, still open from Sprint 5 and Sprint 2 (not repeated here): [S5-01](../s5-harden/01-clean-machine-run.md) clean-machine run from the docs, [S2-03](../s2-extension-builds/03-linux-no-regression.md) Linux build check.

Constraint: new scripts, workflow targets and subcommands need the user's explicit consent before they are written (see `scripts/windows/CLAUDE.md`); the tasks below say where that applies.
